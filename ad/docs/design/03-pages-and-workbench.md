## 二、路由表

| 路径 | 组件 | 允许角色 |
| --- | --- | --- |
| `/login` | Login.vue | 所有人（免登录） |
| `/dashboard` | Dashboard.vue | 已登录 |
| `/orders` | OrderList.vue | CS_MANAGER, BIZ_LEADER |
| `/orders/create` | OrderCreate.vue | CS_MANAGER |
| `/orders/:id` | OrderDetail.vue | CS_MANAGER（自己的）, BIZ_LEADER |
| `/tasks` | TaskList.vue | 已登录 |
| `/tasks/:id` | TaskDetail.vue | 已登录（DESIGNER 只能看自己的） |
| `/forbidden` | Forbidden.vue | 所有人 |

**路由守卫**：未登录跳 `/login`；登录后访问无权限路由跳 `/forbidden`。

**行内按钮 v-if 状态机对齐**：

| 订单状态 | 客户经理可见 | 负责人可见 |
| --- | --- | --- |
| DRAFT | 详情 / 取消 | 详情 / **审核** |
| CONFIRMED | 详情 / **发起变更** / 取消 | 详情 / **分派**（跳到任务列表） |
| IN_PROGRESS | 详情 / 发起变更 / 取消 | 详情 / 取消 |
| PENDING_DELIVERY | 详情 / 发起变更 / **完成交付** / 取消 | 详情 / 取消 |
| COMPLETED | 详情 | 详情 |
| CANCELLED | 详情 | 详情 |

**筛选条件**：客户名模糊 + 状态枚举 + deadline 区间 + 逾期只看（`overdue=true`）+ 分页。

**数据权限**：CS_MANAGER 列表自动只看 `createBy=me`；BIZ_LEADER 看全部。

## 四、关键操作流程时序

### 4.1 设计稿上传时序

```
设计人员 ──► TaskDetail页 ──► POST /tasks/{id}/versions (multipart)
                                        │
                                        ▼
                                   后端 Service:
                                   1. 校验 assignee_id = currentUserId
                                   2. 校验 task_status ∈ 允许上传的状态
                                   3. 算 versionNo = MAX + 1
                                   4. 保存文件到 ./uploads/versions/YYYYMMDD/
                                   5. INSERT design_version
                                   6. UPDATE material_task:
                                      version_count++
                                      task_status → PENDING_CLIENT_REVIEW
                                   7. 上一轮未处理 feedback → processed=true
                                   8. INSERT operation_history (UPLOAD / SUBMIT_NEW_VERSION)
                                        │
                                        ▼
                                   前端 toast "上传成功"
                                   刷新版本时间线
```

### 4.2 客户确认触发订单自动联动时序

```
客户经理 ──► 任务详情页 ──► POST /tasks/{id}/client-confirm
                                        │
                                        ▼
                                   后端 Service:
                                   1. 校验 role = CS_MANAGER
                                   2. 校验订单 create_by = currentUserId
                                   3. 校验 task_status = PENDING_CLIENT_REVIEW
                                   4. 校验 confirmedVersionNo 在 design_version 里存在
                                   5. UPDATE material_task:
                                      task_status → CLIENT_CONFIRMED
                                      client_confirmed_version = X
                                   6. INSERT operation_history (CLIENT_CONFIRM)
                                   7. checkAndPromoteOrderStatus():
                                      SELECT COUNT(*) FROM material_task
                                      WHERE order_id = ? AND
                                            task_status NOT IN
                                            ('CLIENT_CONFIRMED', 'CANCELLED')
                                      如果 COUNT = 0:
                                        UPDATE material_order
                                        SET order_status = 'PENDING_DELIVERY'
                                        INSERT operation_history (AUTO_PROMOTE)
                                   前端 toast "客户已确认，订单可交付"
```

### 4.3 订单变更强制双写时序

```
客户经理 ──► 订单详情页 ──► POST /orders/{id}/changes
                                        │
                                        ▼
                                   后端 Service @Transactional:
                                   1. 校验 role + createBy + 状态机门槛
                                      （DRAFT→422, 终态→409, 非创建人→403）
                                   2. INSERT order_change_record
                                      （type + target + before + after + reason）
                                   3. applyChange():
                                      ├─ ORDER_DEADLINE_CHANGE:
                                      │    UPDATE material_order
                                      │    SET overall_deadline = #{after}
                                      │
                                      ├─ TASK_ADD:
                                      │    INSERT material_task
                                      │    task_no = SELECT MAX(task_no)+1
                                      │    status = PENDING_ASSIGN
                                      │
                                      └─ 其他 4 种: 只存快照
                                   4. INSERT operation_history (CHANGE)
                                        │
                                        ▼
                                   前端 toast "变更已记录"
                                   刷新变更记录 Tab
```

### 4.4 订单取消级联时序

```
客户经理/负责人 ──► 订单详情页 ──► POST /orders/{id}/cancel
                                        │
                                        ▼
                                   后端 Service @Transactional:
                                   1. 校验角色（CS_MANAGER 自己的 / BIZ_LEADER 任意）
                                   2. 校验订单非终态
                                   3. UPDATE material_order:
                                      order_status = CANCELLED
                                      cancel_by = #{me}
                                      cancel_time = NOW()
                                      cancel_reason = #{reason}
                                   4. UPDATE material_task:
                                      SET task_status = CANCELLED
                                      WHERE order_id = #{id}
                                        AND task_status NOT IN
                                            ('CLIENT_CONFIRMED', 'CANCELLED')
                                   5. INSERT operation_history (CANCEL)
                                      描述里带上被级联取消的任务数量
                                        │
                                        ▼
                                   前端 toast "订单已取消，N 项物料同步取消"
                                   刷新订单详情
```

## 五、错误反馈 UX 规范

| HTTP Code | 含义 | 前端表现 |
| --- | --- | --- |
| 400 | 参数校验失败 | el-form-item red border + 字段级 message |
| 401 | 未登录 | axios 拦截器自动 → 清 localStorage → 跳 `/login` |
| 403 | 无权限 | toast "没有权限做这个操作"，按钮应提前 v-if 隐藏 |
| 409 | 状态冲突 | toast + 提示当前状态 + 允许的跳转 |
| 422 | 业务规则拦截 | toast 具体原因（如"草稿直接编辑即可"） |
| 500 | 内部错误 | toast "系统内部错误，请联系管理员" |
